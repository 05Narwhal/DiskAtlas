Each task is tagged with who does it: **F** Fable, **O** `opus-engineer`, **S** `sonnet-builder`, **H** `haiku-runner`. "F then O" means Fable writes the design into the brief and Opus builds it. ## M4. Search

Design: `design/m4-search.md`.

- [x] O: Index build through `scan`, HFS+ sequential catalog pass. `FileSystem::scan` and `identity` (default: breadth-first `read_dir`); HFS+ `scan` in `hfsplus/scan.rs` over `BTree::scan_leaves` (allocated leaves in node order, bitmap-checked, 1 MiB `read_bulk` pieces), links resolved inside the pass. `search/index.rs`, `search/build.rs`: pre-order struct of arrays. Measured in release: HFS+ scan 2.34 M entries/s on a 200,000-file in-memory image (`cargo test -p disk-atlas-lib --release hfsplus_scan_throughput -- --ignored --nocapture`); builder 151–167 ms per million entries, 91.2 bytes/entry at 25.6-byte names (`index_build_throughput`). Not yet run against a real disk, where the scan is bound by sequential read speed.
- [x] O: Query engine: parallel scan, filters, ranking, cancellation, narrowing. `search/query.rs` (memmem over 1 MiB pieces of `folded`, galloping entry cursor, 64-bit rank keys, top 4096 sorted first), `search/order.rs` (column order in parallel). At 1M names, 24 cores, release: rare term 0.43 ms, common 3-letter term 1.37 ms, one letter 6.4–7.2 ms, narrowing step 0.90 ms (`cargo test -p disk-atlas-lib --release --lib query_throughput -- --ignored --nocapture`).
